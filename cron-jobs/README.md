# Accio Work 自媒体AI Agent 定时任务说明

## 概述

本项目基于 [Accio Work改造成自媒体agent方案](./Accio%20Work改造成自媒体agent.pdf) ，将Accio Work的电商Agent能力改造为自媒体AI Agent体系。根据 [自媒体流程](./自媒体流程.xlsx) 中的13个步骤，结合 [AI智能自媒体系统功能说明书](./AI智能自媒体系统功能说明书.docx)，划分出可自动化的定时任务和需要用户参与的手动流程。

## Agent 三层架构

```
┌─────────────────────────────────────────────┐
│          第三层：平台专属Agent（前台）          │
│  墨微(公众号) 墨知(知乎) 墨红(小红书)          │
│  墨推(X/Twitter) 墨拍(视频号/抖音)             │
├─────────────────────────────────────────────┤
│          第二层：运营总监Agent（中控）           │
│                   墨媒                        │
├─────────────────────────────────────────────┤
│          第一层：基础支撑Agent（后台）           │
│  墨笔(内容创作) 墨影(视觉设计)                  │
│  墨风(数据分析) 墨盾(合规风控)                  │
└─────────────────────────────────────────────┘
```

## 流程步骤与自动化划分

### ❌ 不创建定时任务的步骤（需要用户参与）

以下步骤涉及用户输入、人工判断或确认，不适合自动化执行：

| 步骤 | 名称 | 不自动化的原因 |
|------|------|---------------|
| 1 | 学员潜质智能分析 | 需要学员填写潜质评估问卷，是一次性的初始化评估 |
| 2 | 自媒体选题分析 | 需要学员填写选题方向诊断问卷，属于初始化阶段 |
| 3 | 确定运营自媒体平台 | 需要用户确认最终选择的运营平台 |
| 4 | 规划账号基础框架方案 | 需要用户审核和确认账号框架方案 |
| 5 | 制定详细方案 | 需要用户审核和确认详细运营方案 |
| 6 | 提取出学员学习的技能 | 需要人工整理技能培训课件 |
| 8 | 内容创作流程方案 | 需要人工实操测验，验证创作流程的可行性 |

> 💡 步骤1-6属于**账号初始化阶段**，是一次性设置流程，由用户在系统中交互式完成。
> 步骤8需要**人工实操验证**，确保AI生成的创作流程方案切实可行。

### ✅ 创建定时任务的步骤（可自动化执行）

| 编号 | 定时任务 | 对应步骤 | 执行时间 | 执行Agent |
|------|---------|---------|---------|----------|
| 01 | 热点话题抓取 | 步骤7 | 每天 08:00 | 墨风（数据分析） |
| 02 | 内容检测和优化 | 步骤9 | 每天 14:00 | 墨盾（合规风控） |
| 03 | 定时发布 | 步骤10 | 每天 09:00/12:00/18:00/21:00 | 平台专属Agent |
| 04 | 账号信息监控 | 步骤11 | 每天 21:00 | 墨风（数据分析） |
| 05 | 内容运营监控 | 步骤12 | 每天 22:00 | 墨风（数据分析） |
| 06 | 用户运营监控 | 步骤13 | 每天 22:30 | 墨风（数据分析） |
| 07 | 数据日报生成 | 方案补充 | 每天 23:00 | 墨媒（运营总监） |
| 08 | 数据异常预警检测 | 方案补充 | 每4小时 | 墨媒（运营总监） |

## 每日执行时序

```
00:00  ─── 数据异常预警检测 🔍
 ...
04:00  ─── 数据异常预警检测 🔍
 ...
08:00  ─── 热点话题抓取 📡 ──→ 推送话题推荐列表（等待人工确认选题）
        ─── 数据异常预警检测 🔍
09:00  ─── 定时发布（第1轮）📤 ──→ 发布已审核内容
 ...
12:00  ─── 定时发布（第2轮）📤 ──→ 发布已审核内容
        ─── 数据异常预警检测 🔍
 ...
14:00  ─── 内容检测和优化 🛡️ ──→ 检测待发布内容质量（合格→待发布队列，不合格→人工复核）
 ...
16:00  ─── 数据异常预警检测 🔍
 ...
18:00  ─── 定时发布（第3轮）📤 ──→ 发布已审核内容
 ...
20:00  ─── 数据异常预警检测 🔍
21:00  ─── 定时发布（第4轮）📤 ──→ 发布已审核内容
        ─── 账号信息监控 📊 ──→ 各平台账号健康度评估
22:00  ─── 内容运营监控 📈 ──→ 内容效果分析
22:30  ─── 用户运营监控 👥 ──→ 用户行为分析
23:00  ─── 数据日报生成 📋 ──→ 汇总全天数据，推送日报至团队
```

## 关键设计原则

1. **人工确认节点保留**：选题确认和内容审核环节必须经过人工确认，避免AI自主发布风险内容
2. **平台风控意识**：自动发布模拟真人操作间隔，控制发布频率，避免触发平台封号风控
3. **数据安全**：各平台登录态（Cookie/Chrome Profile）严格隔离，敏感信息不出现在报告中
4. **分层预警**：数据异常预警分为紧急/重要/一般三级，避免预警疲劳
5. **闭环运营**：从热点抓取→内容检测→自动发布→数据监控→日报复盘，形成自动化运营闭环
